# Халява.exe — автоматические публикации

Node.js 24 + TypeScript бот для канала [Халява.exe](https://t.me/halyava_exe_hub). Каждый запуск получает активные предложения GamerPower, проверяет их, сохраняет очередь, создаёт русскоязычную подпись и фирменную обложку 1200 × 675, затем публикует не более одного подходящего предложения для каждого канала. Автоматически выбираются только полные игры; внутриигровые бонусы и DLC отключены до проверки их условий. По умолчанию локально работает безопасный `DRY_RUN`. Новые источники и категории доступны в отдельном предварительном просмотре до проверки владельцем.

## Что требуется

- Node.js 24 и npm.
- Telegram-канал и бот с правом публикации (только для реального режима).
- GitHub-репозиторий для работы при выключенном компьютере.

GamerPower не требует ключа и разрешает личное и коммерческое использование при наличии активной ссылки на GamerPower. API просит не превышать 10 запросов/с. Проект делает один запрос к списку за запуск на канал и ещё один к выбранной карточке перед публикацией. [Документация GamerPower](https://www.gamerpower.com/api-read).

## Установка и локальный запуск

### Windows PowerShell

```powershell
cd 'C:\путь\к\проекту'
npm ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm run dev
```

### WSL Ubuntu

```bash
cd /путь/к/проекту
npm ci
test -f .env || cp .env.example .env
npm run dev
```

В текущей рабочей папке `.env` настроен с ID канала, токеном и `DRY_RUN=true`; файл исключён из Git. В новой копии репозитория скопируйте `.env.example` в `.env` и добавьте свои значения. Для локального теста Telegram не нужен: `DRY_RUN=true` получает реальные данные, фильтрует их, создаёт изображения и подписи в `dry-run/<id канала>/`, выводит результат в консоль, не отправляет сообщения и не меняет состояние публикаций. Если новых подходящих предложений нет, это нормальный результат. Папка `dry-run/` исключена из Git.

Проверки: `npm run typecheck`, `npm test`, `npm run lint`, `npm run format:check`. Сборка: `npm run build`; запуск собранного проекта: `npm start`.

## Настройка Telegram

Канал `@halyava_exe_hub` и бот уже созданы. В текущей рабочей папке токен указан в `TELEGRAM_BOT_TOKEN` локального `.env`; в новой копии добавьте его самостоятельно и не отправляйте файл в Git. Команда `npm run telegram:check` без публикации проверит токен через `getMe`, доступ к каналу через `getChat` и право `can_post_messages` через `getChatMember`. Если нужны уведомления об ошибках и ежедневный отчёт, начните личный диалог с ботом и укажите свой числовой ID в `TELEGRAM_ADMIN_ID`.

Для тестовой отправки после отдельного разрешения добавьте бота в отдельный тестовый канал и укажите `TEST_CHANNEL_ID`. Запустите с `TEST_PUBLISH=true`. Этот режим отправляет один пост с изображением, подписью и inline-кнопкой в тестовый канал и не меняет историю основного канала. Для проверки истории основной публикации используйте рабочий запуск после разрешения: один запуск отправляет не более одного поста и сохраняет `messageId` в `data/published.json`.

`TELEGRAM_ADMIN_ID` пока не заполнен по выбору владельца: личные уведомления выключены. Чтобы включить их позже, начните диалог с ботом и узнайте свой числовой ID через `getUpdates`; не публикуйте ответ API, он может содержать личные данные. После публикации бот отправит ссылку на пост и, если выбран, сценарий Shorts. Ошибка личного уведомления не повторяет публикацию в канале. Дневной технический отчёт и сообщения об ошибках тоже используют этот ID.

Для основной локальной публикации задайте `DRY_RUN=false` и запустите `npm run dev`. Локальный JSON сохраняется в `data/`. Если отправка завершилась без понятного ответа, элемент получает статус `uncertain` и автоматически повторно не отправляется. Пост с постоянной ошибкой Telegram 400/403 получает статус `blocked`. Проверьте канал вручную и затем либо перенесите запись в `published.json` с настоящим `messageId` и временем, либо верните статус `queued`, если поста в канале нет и причина ошибки устранена.

## GitHub Actions: работа без компьютера

1. Проект подключён к уже созданному репозиторию [Nkr244/tg](https://github.com/Nkr244/tg) с основной веткой `main`. Workflow по расписанию запускается только из основной ветки.
2. В **Settings → Secrets and variables → Actions** сохранены Repository secrets `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHANNEL_ID`. Repository variable `ENABLE_PUBLISH` управляет автоматической отправкой: `true` включает её, `false` приостанавливает. При необходимости добавьте `TELEGRAM_ADMIN_ID` и `TEST_CHANNEL_ID`.
3. Оставьте стандартные разрешения Actions доступными только для чтения: `publish.yml` запрашивает `contents: write` для собственных коммитов `data/*.json`. Если ветка защищена от прямых коммитов, создайте отдельную незапрещённую ветку как основную для этого проекта или настройте допустимый способ записи состояния; иначе живую публикацию включать нельзя.
4. На вкладке **Actions → Collect and publish → Run workflow** выберите `dry`. Скачайте артефакт `preview-…` и проверьте подписи и обложки.
5. Выберите `test` для одной публикации в отдельный тестовый канал.
6. После разрешения владельца и успешных проверок установите `ENABLE_PUBLISH=true`. Только это значение включает отправку в основной канал, включая ручной режим `live`; `false` оставляет DRY_RUN.

Workflow проверяет источники каждые 15 минут по расписанию `:07`, `:22`, `:37`, `:52` UTC и может запускаться вручную. Само окно публикаций задаётся в `config/channels.json` по часовому поясу канала: `Europe/Moscow`, 09:00–22:00, до 5 постов за местные сутки, интервал от 60 минут. GitHub может задержать или пропустить запуск; точное время поста не гарантируется. Запуски сериализованы через `concurrency`. После формирования очереди, перед запросом Telegram и после подтверждения бот коммитит JSON-состояние. Если предварительный коммит не удался, запрос Telegram не производится. Внешний Cloudflare Worker владельца не хранится в этом репозитории; видимые запуски `workflow_dispatch` не доказывают его 15-минутную работу. Встроенное расписание оставлено до подтверждения внешнего запуска на нескольких интервалах.

GitHub Actions на стандартном `ubuntu-latest` в публичном репозитории бесплатны. Оба workflow пропускают задания, если репозиторий станет приватным; npm-кэш выключен. Артефакты ручного DRY_RUN хранятся один день, а живой режим их не создаёт. Следите за текущими [правилами оплаты](https://docs.github.com/en/billing/concepts/product-billing/github-actions) и [лимитами](https://docs.github.com/en/actions/reference/limits). По [правилам расписания](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows) запланированный workflow в публичном репозитории может отключиться после 60 дней без активности; коммиты состояния обычно поддерживают активность, но при отсутствии новых данных стоит проверять вкладку Actions.

## Конфигурация и расширение

`config/channels.json` содержит список каналов. Каждый канал задаёт `id`, имя, `telegramChatIdEnv`, источники, категории, часовой пояс и расписание. Для дополнительного канала добавьте объект с уникальным ID и отдельную переменную окружения для chat ID. Сейчас один источник: `gamerpower`; адаптеры реализуют интерфейс `Source` из `src/types/index.ts` и регистрируются в `src/sources/index.ts`. Можно добавить адаптер для Steam, Epic, GOG, RSS или других разрешённых источников без изменения формата очереди.

### Новые источники: предварительный просмотр

Адаптеры LootScraper (Epic/GOG/Steam) и кураторских GitHub-репозиториев подключены только к `npm run preview:sources`. Команда не вызывает Telegram и не меняет очередь или историю. Результаты сохраняются в `dry-run/new-sources/`: `.jpg` — обложка, `.txt` — подпись и кнопка, `.shorts.txt` — текстовый пакет для Gemini, `.json` — структурированная карточка для будущего сайта. Новые категории `ai` и `opensource` не опубликованы автоматически до просмотра примеров и отдельного разрешения владельца.

Типы предложений различаются в модели и тексте: временная раздача, постоянно бесплатный продукт, бесплатная лицензия, бесплатный тариф, открытый код, скидка и пробный доступ. Открытый проект не называется временной раздачей. Обложки меняют рубрику и бейдж для новой категории и используют только собственные SVG-фигуры. Сценарии Shorts создаются текстом не более чем для двух подходящих публикаций за сутки; видео не генерируется и не загружается. После фактической публикации текст сценария сохраняется в `data/published.json`.

LootScraper предоставляет [публичные Atom-ленты](https://github.com/eikowagenknecht/lootscraper#rss-feeds) и прямые ссылки магазинов. Адаптер использует заголовок, тип, ссылку и календарную дату окончания; автоматически подтянутые описания игнорируются, поскольку сам источник предупреждает о возможной ошибке сопоставления игр. Уже бесплатные free-to-play игры исключаются. Время окончания в ленте не содержит часового пояса, поэтому бот прекращает рассматривать запись с начала указанного дня по UTC и предлагает сверить точное время в магазине. Кураторские проекты читаются через [GitHub REST API](https://docs.github.com/en/rest/repos/repos); используются только доступные и недавно обновлённые репозитории с явной лицензией. Неавторизованный API ограничен [60 запросами в час на IP](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api); предварительный прогон делает до четырёх запросов, поэтому его не следует запускать каждые 15 минут.

IsThereAnyDeal пока не подключён: [API](https://docs.isthereanydeal.com/) использует ключ, а цена и условия скидки требуют отдельной проверки. Giveaway of the Day не включён: доступность предполагаемой RSS-ленты и правила повторного использования данных не удалось подтвердить. То же относится к SharewareOnSale и произвольным страницам магазинов. F-Droid и Hugging Face требуют отдельной проверки метаданных, лицензий и качества подборки. Отсутствие этих источников не мешает работе GamerPower.

Все данные приводятся к `Offer`. Неизвестные цена, дата и регион остаются пустыми. Поле `worth` GamerPower не приравнивается к подтверждённой прежней цене магазина. Английское описание не публикуется без перевода; русская подпись строится по проверенным полям. Фирменная обложка использует цвета `#0B0E13`, `#39FF88`, `#F5F5F5`, `#FFCC00`, мотив терминала и слоган «Запусти халяву». Генератор подбирает размер заголовка и одно из трёх оформлений. В обложках используются только собственные SVG-элементы; изображения игр не подгружаются без подтверждённых прав. URL проверяется на HTTPS и официальный домен GamerPower; выбранная карточка повторно проверяется через detail API перед отправкой. Обычная HTML-страница GamerPower может отвечать Cloudflare 403 на автоматический HEAD-запрос, поэтому её доступность в браузере бот не обещает. Статус `Active` и дата окончания проверяются при сборе и повторно перед публикацией. Предложения с известным требованием ARP, покупки или подписки отсекаются по явным формулировкам; ручная проверка качества источника всё равно полезна.

Время в датах GamerPower приходит без часового пояса. Бот трактует его как UTC для сравнения, а в подписи показывает исходную календарную дату. Если источник указывает типовое окончание в 23:59, бот консервативно перестаёт публиковать предложение с начала этой даты по UTC: магазин может завершить акцию раньше. Перед отправкой карточка повторно проверяется через API; точный момент завершения акции зависит от правил магазина.

`data/queue.json` — очередь с состояниями `queued`, `sending`, `uncertain`, `blocked`; `data/published.json` — отправленные посты и Telegram message ID; `data/reports.json` — даты ежедневных отчётов. Не удаляйте эти файлы при обновлении проекта. Их коммиты в публичном репозитории открыты всем: они содержат названия, ссылки и ID сообщений, но не токен.

## Диагностика

- Нет новых постов: проверьте `Actions`, часовой пояс, дневной лимит, очередь и актуальные предложения API. Пустая выдача API (HTTP 201) допустима.
- Ошибка 403 Telegram: проверьте токен, ID и права бота в канале.
- Ошибка сохранения состояния: проверьте `contents: write`, защиту ветки и доступность GitHub. При статусе `sending` или `uncertain` сначала проверьте канал, не повторяйте отправку вслепую.
- Ошибка источника не прерывает обработку других источников или уже сохранённой очереди. При наличии `TELEGRAM_ADMIN_ID` отправляется уведомление.
- Ежедневный технический отчёт отправляется после 21:00 по часовому поясу канала в ближайший успешный запуск; он содержит число публикаций, ожидающих и проблемных записей, ошибки источников и признак отсутствия подходящих предложений более суток. Повторное уведомление об одной и той же ошибке источника в течение дня подавляется.

Проект не содержит платных API, хостинга или обходов ограничений AI. Дальнейшие VK, сайт, генерация видео и вызовы LLM не реализованы.
