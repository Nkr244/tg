# Халява.exe — автоматические публикации

Node.js 24 + TypeScript бот для канала [Халява.exe](https://t.me/halyava_exe_hub). Каждый запуск получает активные предложения GamerPower, проверяет их, сохраняет очередь, создаёт русскоязычную подпись и фирменную обложку 1200 × 675, затем публикует не более одного подходящего предложения для каждого канала. По умолчанию работает только безопасный `DRY_RUN`. Тематика канала: бесплатные игры, раздачи, программы и цифровые находки; адаптер программ пока не подключён.

## Что требуется

- Node.js 24 и npm.
- Telegram-канал и бот с правом публикации (только для реального режима).
- GitHub-репозиторий для работы при выключенном компьютере.

GamerPower не требует ключа и разрешает личное и коммерческое использование при наличии активной ссылки на GamerPower. API просит не превышать 10 запросов/с. Проект делает один запрос к списку за запуск на канал и ещё один к выбранной карточке перед публикацией. [Документация GamerPower](https://www.gamerpower.com/api-read).

## Установка и локальный запуск

### Windows PowerShell

```powershell
cd 'C:\путь\к\проекту'
npm ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm run dev
```

### WSL Ubuntu

```bash
cd /путь/к/проекту
npm ci
test -f .env || cp .env.example .env
npm run dev
```

В текущей рабочей папке `.env` настроен с ID канала, токеном и `DRY_RUN=true`; файл исключён из Git. В новой копии репозитория скопируйте `.env.example` в `.env` и добавьте свои значения. Для локального теста Telegram не нужен: `DRY_RUN=true` получает реальные данные, фильтрует их, создаёт изображения и подписи в `dry-run/<id канала>/`, выводит результат в консоль, не отправляет сообщения и не меняет состояние публикаций. Если новых подходящих предложений нет, это нормальный результат. Папка `dry-run/` исключена из Git.

Проверки: `npm run typecheck`, `npm test`, `npm run lint`, `npm run format:check`. Сборка: `npm run build`; запуск собранного проекта: `npm start`.

## Настройка Telegram

Канал `@halyava_exe_hub` и бот уже созданы. В текущей рабочей папке токен указан в `TELEGRAM_BOT_TOKEN` локального `.env`; в новой копии добавьте его самостоятельно и не отправляйте файл в Git. Команда `npm run telegram:check` без публикации проверит токен через `getMe`, доступ к каналу через `getChat` и право `can_post_messages` через `getChatMember`. Если нужны уведомления об ошибках и ежедневный отчёт, начните личный диалог с ботом и укажите свой числовой ID в `TELEGRAM_ADMIN_ID`.

Для тестовой отправки после отдельного разрешения добавьте бота в отдельный тестовый канал и укажите `TEST_CHANNEL_ID`. Запустите с `TEST_PUBLISH=true`. Этот режим отправляет один пост с изображением, подписью и inline-кнопкой в тестовый канал и не меняет историю основного канала. Для проверки истории основной публикации используйте рабочий запуск после разрешения: один запуск отправляет не более одного поста и сохраняет `messageId` в `data/published.json`.

Для основной локальной публикации задайте `DRY_RUN=false` и запустите `npm run dev`. Локальный JSON сохраняется в `data/`. Если отправка завершилась без понятного ответа, элемент получает статус `uncertain` и автоматически повторно не отправляется. Пост с постоянной ошибкой Telegram 400/403 получает статус `blocked`. Проверьте канал вручную и затем либо перенесите запись в `published.json` с настоящим `messageId` и временем, либо верните статус `queued`, если поста в канале нет и причина ошибки устранена.

## GitHub Actions: работа без компьютера

1. Проект подключён к уже созданному репозиторию [Nkr244/tg](https://github.com/Nkr244/tg) с основной веткой `main`. Workflow по расписанию запускается только из основной ветки.
2. В **Settings → Secrets and variables → Actions** уже сохранены Repository secrets `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHANNEL_ID`, а Repository variable `ENABLE_PUBLISH` установлена в `false`. При необходимости добавьте `TELEGRAM_ADMIN_ID` и `TEST_CHANNEL_ID`.
3. Оставьте стандартные разрешения Actions доступными только для чтения: `publish.yml` запрашивает `contents: write` для собственных коммитов `data/*.json`. Если ветка защищена от прямых коммитов, создайте отдельную незапрещённую ветку как основную для этого проекта или настройте допустимый способ записи состояния; иначе живую публикацию включать нельзя.
4. На вкладке **Actions → Collect and publish → Run workflow** выберите `dry`. Скачайте артефакт `preview-…` и проверьте подписи и обложки.
5. Выберите `test` для одной публикации в отдельный тестовый канал.
6. `ENABLE_PUBLISH` должен оставаться `false` до отдельного разрешения на реальные публикации. Только значение `true` включает отправку в основной канал, включая ручной режим `live`.

Workflow запускается раз в час в **:17 UTC**, чтобы избежать нагрузки в начале часа. Само окно публикаций задаётся в `config/channels.json` по часовому поясу канала: по умолчанию `Europe/Moscow`, 09:00–22:00, до 5 постов за местные сутки, интервал от 60 минут. GitHub может задержать или пропустить запуск; точное время поста не гарантируется. Запуски сериализованы через `concurrency`. После формирования очереди, перед запросом Telegram и после подтверждения бот коммитит JSON-состояние. Если предварительный коммит не удался, запрос Telegram не производится.

GitHub Actions на стандартных runner для публичных репозиториев бесплатны; для приватных действует квота. Следите за текущими [правилами оплаты](https://docs.github.com/en/billing/concepts/product-billing/github-actions) и [лимитами](https://docs.github.com/en/actions/reference/limits). По [правилам расписания](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows) запланированный workflow в публичном репозитории может отключиться после 60 дней без активности; коммиты состояния обычно поддерживают активность, но при отсутствии новых данных стоит проверять вкладку Actions.

## Конфигурация и расширение

`config/channels.json` содержит список каналов. Каждый канал задаёт `id`, имя, `telegramChatIdEnv`, источники, категории, часовой пояс и расписание. Для дополнительного канала добавьте объект с уникальным ID и отдельную переменную окружения для chat ID. Сейчас один источник: `gamerpower`; адаптеры реализуют интерфейс `Source` из `src/types/index.ts` и регистрируются в `src/sources/index.ts`. Можно добавить адаптер для Steam, Epic, GOG, RSS или других разрешённых источников без изменения формата очереди.

Все данные приводятся к `Offer`. Неизвестные цена, дата и регион остаются пустыми. Поле `worth` GamerPower не приравнивается к подтверждённой прежней цене магазина. Английское описание не публикуется без перевода; русская подпись строится по проверенным полям. Фирменная обложка использует цвета `#0B0E13`, `#39FF88`, `#F5F5F5`, `#FFCC00`, мотив терминала и слоган «Запусти халяву». Если права на исходную иллюстрацию не подтверждены, используется собственная обложка без неё. URL проверяется на HTTPS и официальный домен GamerPower; выбранная карточка повторно проверяется через detail API перед отправкой. Обычная HTML-страница GamerPower может отвечать Cloudflare 403 на автоматический HEAD-запрос, поэтому её доступность в браузере бот не обещает. Статус `Active` и дата окончания проверяются при сборе и повторно перед публикацией. Предложения с известным требованием ARP, покупки или подписки отсекаются по явным формулировкам; ручная проверка качества источника всё равно полезна.

Время в датах GamerPower приходит без часового пояса. Бот трактует его как UTC для сравнения, а в подписи показывает исходную календарную дату. Окончательную актуальность подтверждает повторный запрос к API; точный момент завершения акции зависит от правил магазина.

`data/queue.json` — очередь с состояниями `queued`, `sending`, `uncertain`, `blocked`; `data/published.json` — отправленные посты и Telegram message ID; `data/reports.json` — даты ежедневных отчётов. Не удаляйте эти файлы при обновлении проекта. Их коммиты в публичном репозитории открыты всем: они содержат названия, ссылки и ID сообщений, но не токен.

## Диагностика

- Нет новых постов: проверьте `Actions`, часовой пояс, дневной лимит, очередь и актуальные предложения API. Пустая выдача API (HTTP 201) допустима.
- Ошибка 403 Telegram: проверьте токен, ID и права бота в канале.
- Ошибка сохранения состояния: проверьте `contents: write`, защиту ветки и доступность GitHub. При статусе `sending` или `uncertain` сначала проверьте канал, не повторяйте отправку вслепую.
- Ошибка источника не прерывает обработку других источников или уже сохранённой очереди. При наличии `TELEGRAM_ADMIN_ID` отправляется уведомление.
- Ежедневный технический отчёт отправляется после 21:00 по часовому поясу канала в ближайший успешный запуск; это краткая сводка по опубликованным постам и очереди.

Проект не содержит платных API, хостинга или обходов ограничений AI. Дальнейшие VK, сайт, видео и LLM в MVP не реализованы.
