# Халява.exe — сайт-каталог

Статический сайт на Nuxt 4, Vue 3, TypeScript и SCSS. Сайт читает только подтверждённую историю публикаций бота. Отдельная база данных, платный API и сервер не нужны.

## Локальный запуск

Из корня репозитория:

```bash
npm ci
node --import tsx website/scripts/export.ts
cd website
npm ci
npm run dev
```

Откройте `http://localhost:3000`. Для статической сборки используйте `npm run build`; результат — `website/.output/public/`. Для проверки: `npm run typecheck`, `npm test`, `npm run lint`, `npm run format:check`, `npx playwright test`.

## Данные и синхронизация

`scripts/export.ts` читает `data/published.json` (или `PUBLISHED_FILE`), допускает запись только с положительным Telegram message ID, собирает явно разрешённые публичные поля и формирует `app/data/catalog.json` и `public/catalog.json`. Очередь, отчёты, `.env`, токены, внутренние промпты и технические журналы не читаются. Обложки повторно создаются существующим генератором бота и сохраняются в WebP. Бот и его отправка в Telegram не изменены. При ошибке экспорта или сборки Telegram-публикация не повторяется.

В сохранённой истории сейчас три подтверждённые публикации. Для них есть точные русскоязычные пересказы фактов из исходных описаний. Для будущих публикаций без русского описания экспорт формирует короткое фактическое пояснение по известным полям и направляет к источнику. Обычная цена, скидка, ОС и доступность в России не додумываются. `PC` не превращается автоматически в `Windows`. Внешние ссылки допускают только HTTPS.

Workflow `website-preview.yml` работает только в `dev`, получает **свежую** историю из `main`, запускает экспорт, тесты и статическую сборку, затем сохраняет артефакт GitHub Actions. Он не имеет секретов и прав на запись, не отправляет посты и не развёртывает сайт. Коммиты бота через стандартный `GITHUB_TOKEN` не запускают другой workflow; после разрешения на размещение следует добавить независимый механизм пересборки, например `workflow_run` на успешный `Collect and publish` в default branch, либо отдельный внешний хостинг с запланированным pull/build. До такого разрешения этот workflow срабатывает на кодовые изменения `dev`.

## SEO и публикация

Dev-сборка получает `noindex,nofollow`, `robots.txt` с `Disallow: /` и пустой sitemap. Для будущей публичной сборки нужны `NUXT_PUBLIC_SITE_URL=https://...` и `SITE_INDEXABLE=true`. Экспорт создаст sitemap только для главной, страницы проекта, наполненных разделов и подтверждённых публикаций. Пустые разделы доступны по прямому адресу, но не появляются в основной навигации и sitemap. На страницах есть canonical, Open Graph и Article JSON-LD. После выбора хостинга можно подключить Яндекс Вебмастер и Google Search Console без изменений в модели данных.

Срок акции проверяется по сохранённой дате. Для точного статуса в статическом HTML нужна регулярная пересборка после размещения. Пользователю всегда предлагается проверить первоисточник.

## Бесплатный хостинг

Для будущего размещения предпочтителен Cloudflare Pages на `*.pages.dev`: статическая сборка, бесплатный технический домен, до 500 сборок в месяц и 20 000 файлов на Free. GitHub Pages на `*.github.io` тоже подходит для некоммерческого информационного проекта, но имеет мягкий лимит 100 ГБ трафика в месяц, лимит 1 ГБ на сайт и ограничения на коммерческое использование. Условия и доступность из России нужно проверить перед запуском на реальных сетях аудитории; гарантировать доступность конкретного CDN нельзя. Монетизацию следует сверить с действующими правилами выбранного сервиса. Домена и платного тарифа сейчас нет.

Источники: [Cloudflare Pages Limits](https://developers.cloudflare.com/pages/platform/limits/), [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).
